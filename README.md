# Probe-Geometry Alignment: Erasing the Cross-Sequence Memorization Signature Below Chance

Code, figures, and JSON results for the paper on cross-sequence memorization probing in transformers, the causal-separability finding, and the constructive method (probe-geometry alignment, PGA).

This repository contains every notebook used to produce the quantitative claims in the paper, all figures generated by those notebooks (rendered at 300 DPI), and every JSON output file the paper consumes.

---

## TL;DR

1. **A leave-one-out cross-sequence probing protocol** that tests whether the memorization signature *generalizes* across held-out sequences. On Pythia-70M, GPT-2-Medium, and Mistral-7B the signature gives memorization-specific gaps of `+0.32`, `+0.19`, `+0.30` over a pure-distinguishability baseline, against a random-initialization control (Pythia-70M) whose deep-layer gap collapses to `−0.04` at L6.

2. **Direct evidence that the probe direction is causally separable from recall.** Projecting it out of the L4 residual on Pythia-70M collapses the local cross-sequence gap (`+0.44 → −0.19`) but the signature is reconstituted by L6, while behavioural recall barely changes.

3. **A regime distinction.** A probe trained on naturally memorized content does not classify fine-tuning-injected secrets as memorized; the two regimes leave representationally distinct traces.

4. **Probe-geometry alignment (PGA), the first surgical erasure method to drive cross-sequence probes below random chance.** PGA aligns activations along the probe's own readout direction at each depth (one scalar per depth, not the full residual). Below-chance collapse at four scales:
   - Toy 9+9: depth-4 = `0.17`
   - Pythia-70M: L5 = `0.29`, L6 = `0.14`
   - Mistral-7B mid-layers (L24, L28): `0.42`
   - GPT-2 Medium via MD-PGA k=2 at L21: `0.06`

   Robust to six adversarial probe variants. Adversarial PGA (iterative orthogonal subspace augmentation) further defeats re-fit attacker probes while preserving five zero-shot capability benchmarks (HellaSwag, PIQA, BoolQ, ARC-Easy, WinoGrande) within 2.9 percentage points (max BoolQ |Δ|; mean Δacc = +0.2pp).

## Reproducing the headline numbers

Each notebook is a standalone Run-All. Open in Jupyter or Colab and run cells top to bottom. Outputs go into `results/` (JSON) and `figures/` (PNG).

The four `gpt2m_*` / `mistral7b_multiseed` notebooks reuse cached activations between runs. Run `gpt2m_multiseed.ipynb` first to populate the activation cache; the bootstrap and jackknife notebooks then reuse it.

The MLDU-E pipelines depend on `pythia_memorized.json` / `pythia_clean.json` (auto-built by pipeline3 / pipeline4 the first time, cached afterwards) and on the toy 9+9 phase-1 checkpoint (auto-trained by pipeline1).

### Reproducibility notes

The Pythia-70M post-PGA per-layer values (`L5 = 0.286`, `L6 = 0.143`) are deterministic across re-runs because cell 11 of the standalone Pythia notebook resets PyTorch / NumPy / Python RNGs immediately before LoRA initialization. Pipeline-3 cell 102 and pipeline-4 cell 15 carry the same patch, so all three notebooks that train Pythia-PGA produce identical post-PGA probe values from a fresh kernel.

For full CUDA-level determinism (slower) you can additionally set `CUBLAS_WORKSPACE_CONFIG=:16:8` before importing torch and uncomment the `torch.backends.cudnn.deterministic = True` lines in the patched cells.

## Dependencies

The notebooks were run on Google Colab (T4 for small models, L4 or A100 for Mistral-7B / Mistral mega-pipeline). Core requirements:

- `torch`, `transformers`, `datasets==2.21.0`, `accelerate`
- `peft >= 0.5` for LoRA fine-tunes (Pythia / Mistral pipelines)
- `lm-eval == 0.4.4` for capability benchmarks (HellaSwag, PIQA, BoolQ, ARC-Easy, WinoGrande)
- `scikit-learn`, `numpy`, `matplotlib`

The `datasets==2.21.0` pin is required because newer versions removed support for dataset loading scripts, which breaks PIQA loading in lm-eval 0.4.4.
